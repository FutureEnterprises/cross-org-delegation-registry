# Requirements anchor: R1-R9

The requirement axis. Answers "what must a mechanism provide."

**Authoritative text:** `draft-reece-wimse-cross-org-delegation-00`,
Section 5. The glosses below are editorial one-liners for navigation only;
the normative text is Morgan Reece's draft. Entries in this registry are
evaluated against the revision named in each row, currently reece-00.

Under revision on the WIMSE list: R2 is being refined (splitting anchor
acquisition from anchor binding, with the irreducible first-contact root
moved to a Security Consideration). Until that revision posts, this
registry cites R2 as written in reece-00 and does not race the in-flight
text.

| ID | Gloss |
|----|-------|
| R1 | Recursive attenuation: authority narrows at each hop, re-checked at verification. |
| R2 | Cross-organizational verification without a bilateral arrangement specific to the interaction. |
| R3 | No runtime callback: verification is local and offline given conveyed material. |
| R4 | Proof of possession by the presenter. |
| R5 | Principal binding and invariance along the chain. |
| R6 | Dual-axis authorization (agent authority and bound-principal entitlements). |
| R7 | Authentic bounded-staleness revocation. |
| R8 | Tamper-evident composable audit. |
| R9 | Format and transport agnosticism. |

To propose changes to a requirement, take it to the WIMSE list and to the
requirements author; this registry tracks reece-* as published.
